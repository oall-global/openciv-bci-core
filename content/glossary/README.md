# 概念手册 · 内容编写指南

app 里「工具与设置 → 概念手册」的全部内容都在这个文件夹里。补充内容只需要编辑这里的文件，不需要改代码。

## 文件夹结构

```
content/glossary/
  chapters.json        章节顺序，以及每章包含哪些条目（按顺序）
  _template.md         新条目的模板
  images/              所有配图
  bci/  kinds/  anatomy/  signal/  rhythm/  processing/  quality/
  task/  experiment/  data/  safety/  faq/  refs/
                       每个章节一个文件夹，每个条目一个 .md 文件
```

已经按完整格式写好的示例：`rhythm/alpha.md`，配图 `images/alpha-eyes-spectrum.svg`。

当前内容包含 73 个条目、13 章、18 张自绘 SVG，以及复用 app 现有模型的脑区交互图。原有 41 个条目的 id 保持不变；大脑结构章节增加了 15 个部位的独立条目。另有信号处理、实验规范、安全伦理、常见问题，以及 `refs/terminology.md` 中的全条目中英索引。新增条目时也请更新术语索引。

SVG 配图为静态教学示意；`chance.svg` 根据均衡二分类、独立试次、单次比较的二项分布计算。图中数据均不是用户的实时记录。脑区交互图是解剖教学展示，不接入脑电；交互电极图与嵌入式实时演示仍需另外开发。

## 复用 app 的大脑模型

在独立一行写 `:::brain-atlas frontal` 可嵌入脑区图。参数为 `brain-regions.json` 的部位 id，例如 `motor`、`occipital`、`hippocampus`、`thalamus`；检查工具会验证标记。交互图支持旋转、五种视角、内部透视、选区高亮和完整条目跳转，无法加载时仍保留文字说明。

`brain-regions.json` 维护短说明和真实网格名；各 `anatomy/region-*.md` 维护完整正文。更新时两者应保持一致。部分部位只覆盖现有模型中的子区，应保留范围说明，不能猜测没有建模的结构。模型沿用 `public/licenses/BrainAtlas.txt` 的署名和 CC BY-SA 3.0 许可；这里不是个体脑扫描或脑源定位。

补充内容时区分三类数字：文献中的典型范围、当前软件实现参数、教学算例。软件参数按当前代码核对，升级实现后要同步复核；尤其注意采样率、佩戴阈值、触发模式、随机水平以及数据外发边界。

## 修改已有条目

直接编辑对应的 `.md` 文件。文件开头 `---` 之间的部分是条目信息：

| 字段 | 说明 |
|---|---|
| `id` | 条目编号，全手册唯一。**已有条目不要改**：界面上的「?」靠它找到条目 |
| `title` | 标题 |
| `short` | 一句话解释，**不超过 80 个字**。作为界面上「?」弹窗的摘要 |
| `see` | 「?」弹窗里的「界面上」：这个概念在屏幕上具体是哪个东西、数字是什么意思，**不超过 60 个字**（选填，界面上带「?」的条目建议都写） |
| `tip` | 「?」弹窗里的「怎么做」：看到它之后该怎么操作或调整，**不超过 60 个字**（选填） |
| `level` | `入门`、`进阶` 或 `专业` |
| `en` | 英文术语 |
| `related` | 相关条目的 id，用逗号分隔，显示在条目末尾 |

## 新增条目

1. 复制 `_template.md` 到对应章节的文件夹，用 id 作为文件名，例如 `rhythm/mu.md`。
2. 填写开头的条目信息和正文。
3. 在 `chapters.json` 对应章节的 `entries` 里加上这个 id，位置决定它在目录里的顺序。
4. 新增章节：在 `chapters.json` 里加一项 `{ "id": "…", "title": "…", "entries": [] }`，并建同名文件夹。

## 正文的结构（每个条目都按这个顺序）

| 小节 | 写什么 | 要求 |
|---|---|---|
| `## 原理` | 为什么会这样 | 2–4 段，讲到高中生能看懂 |
| `## 图示` | 1–2 张图 | 见下方配图要求 |
| `## 典型数值` | 常见范围的表格 | 给范围，不给绝对值；写清单位 |
| `## 在本软件里` | 在哪个页面能看到、怎么用 | 用 app 里的实际名称，例如「信号工作台 · 主图」 |
| `## 常见误区` | 容易误解的地方 | 用 `> [!误区]` 或 `> [!注意]` 框起来 |
| `## 参考` | 文献 | 教材、综述或经典论文 |

内容少的条目可以省略某些小节，但顺序不变。

## 支持的写法

| 写法 | 效果 |
|---|---|
| `## 小节标题`、`### 小标题` | 标题 |
| 空一行分段 | 段落 |
| `**加粗**` | 加粗 |
| `- 内容` / `1. 内容` | 列表 |
| 表格：`\| 列 \| 列 \|`，第二行 `\|---\|---\|` | 表格 |
| `![说明](images/文件名.svg "图注")` | 图片，图注显示在图片下方 |
| `> [!提示] 标题` 下一行写内容 | 提示框（还有 `[!注意]`、`[!误区]`） |
| `[[alpha]]` 或 `[[alpha\|α 节律]]` | 链接到手册里的另一个条目 |
| `[文字](https://…)` | 外部链接，在系统浏览器中打开 |

不支持 HTML 标签。

## 配图要求

- 格式：**优先 SVG**（矢量，缩放清晰），其次 PNG。放在 `images/` 文件夹，用英文小写和连字符命名，例如 `alpha-eyes-spectrum.svg`。
- 尺寸：宽 640 像素左右，宽高比 2:1 到 16:9。
- 配色：深色背景 `#111715`，文字 `#e6eeea` / `#9aa9a2`，强调色和 app 一致：青 `#32a0a5`、琥珀 `#f0aa3c`、米白 `#fff5d2`、绿 `#5fd3a4`。
- 图里的文字用中文，字体用"Microsoft YaHei UI"。
- 不使用来源不明的网络图片。自己绘制，或使用明确允许再使用的素材，并在图注里注明来源。
- 示意图要在图注里写明"示意"，避免读者当成真实测量结果。

## 写作规范

- **语气**：正式、平实，不用夸张或孩子气的说法。
- **不出现任何品牌或厂商名称**：其他设备、软件、公司都不出现。需要提到时用通用说法，如"开源放大器""业内通用的方法"。
- **准确**：数值给常见范围，并注明"因人而异"等前提；不做医疗或诊断性表述；不把示意图、模拟效果说成测量结果。
- **不夸大能力**：脑机接口识别的是状态，不能读出具体想法。
- **引用**：以教材、综述、经典论文为主，格式为"作者. 标题. 期刊或出版社, 年份."。

## 检查和预览

1. 检查（格式、id、图片、链接、品牌名）：在项目根目录运行 `npm run check:glossary`，有问题会逐条列出。
2. 预览：运行 `npm run build` 后打开 app，进入「工具与设置 → 概念手册」。
3. 提交：通过 git 提交 `content/glossary/` 下的改动，或者把改过的文件发给开发同事。
